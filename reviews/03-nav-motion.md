# Code Review: Navigation, Motion, Accessibility & Performance

## Real Bugs

- **High** — `src/components/Nav.tsx:40`: Initializing scroll detection with `rafId = requestAnimationFrame(handleScroll)` assigns `rafId` before `handleScroll` runs, causing `handleScroll` to detect `rafId !== null` and return immediately without scheduling the inner callback, permanently disabling scroll detection. Call `handleScroll()` synchronously on mount without setting `rafId`.
- **High** — `src/components/WorkIndex.tsx:97`: The FLIP animation leaves inline `transform: none` and a 300ms inline `transition` permanently on card elements, breaking card hover transitions and corrupting subsequent bounding client rect measurements. Remove inline `transform` and `transition` styles in a `transitionend` listener once the FLIP animation completes.
- **High** — `src/components/WorkIndex.tsx:49`: Filtered-out projects are immediately removed from `filteredProjects` and unmounted without animating out, violating the SPEC N requirement that filtered-out cards animate out using the FLIP technique. Retain exiting cards during a transition phase to animate their opacity and scale before unmounting.
- **High** — `src/components/case-study/Toc.tsx:99`: Both `variant="chip-row"` and `variant="rail"` are rendered simultaneously in `src/app/work/[slug]/page.tsx`, causing duplicate `keydown` listeners on `window` that trigger two scroll calls and two history entries on every `j`/`k` press. Hoist keyboard navigation to a single parent listener or guard the listener so only the currently visible variant handles the event.
- **Medium** — `src/components/WorkIndex.tsx:28`: The URL hash filter is applied in `useEffect` after hydrating with `"All"`, causing a visible layout flicker and flash of all projects on first load when navigating directly to `#automotive`, `#spatial`, or `#health`. Initialize filter state synchronously using `useLayoutEffect` to apply the hash filter before paint.
- **Medium** — `src/components/case-study/Toc.tsx:105`: `labelledSections` is re-created as a new array on every render, causing `useEffect` to tear down and recreate its `IntersectionObserver` and window keydown listener whenever `activeId` updates. Memoize `labelledSections` with `useMemo` so its array reference remains stable across re-renders.
- **Medium** — `src/components/CommandPalette.tsx:210`: The `/` key shortcut handler does not verify that modifier keys are inactive, causing `Cmd+/` and `Ctrl+/` to intercept browser or IDE shortcuts and open the palette. Check `!e.metaKey && !e.ctrlKey && !e.altKey` before opening the modal on `/`.
- **Medium** — `src/components/IntentPicker.tsx:87`: The sliding tab highlight transitions layout properties `width` and `height`, violating SPEC M which permits only `transform`, `opacity`, `clip-path`, and `filter` animations. Use a fixed-dimension highlight element animated exclusively via `transform: translate(...) scale(...)`.
- **Low** — `src/app/globals.css:13`: The `--step-hero` custom property is defined as `clamp(2.125rem, 1.4rem + 3.6vw, 5rem)` instead of `clamp(2.5rem, 1.6rem + 3.6vw, 5rem)` as required by SPEC R. Change the clamp definition to `clamp(2.5rem, 1.6rem + 3.6vw, 5rem)`.
- **Low** — `src/components/case-study/Figure.tsx:24`: Setting `wide ? "w-full" : "max-w-[42rem]"` inside a 9-column container limits the figure to columns 4–12 instead of breaking out to the full container width on `lg+` as specified in SPEC V. Apply breakout positioning or negative margins on `lg+` when `wide` is true so the figure spans all 12 container columns.

## Accessibility Problems

- **High** — `src/components/Nav.tsx:75`: The mobile navigation focus trap only searches within `sheetRef` and excludes the toggle button (`toggleButtonRef`), allowing Shift+Tab to escape into the page header and preventing keyboard users from ever reaching the close button. Include the toggle button in the circular focus loop or place the close button inside `sheetRef`.
- **Medium** — `src/components/Nav.tsx:280`: The mobile navigation sheet locks body scroll and traps focus without declaring `role="dialog"` or `aria-modal="true"`, preventing screen readers from recognizing the modal boundary. Add `role="dialog"` and `aria-modal="true"` to the mobile nav sheet container.
- **Medium** — `src/components/CommandPalette.tsx:167`: Focus is not returned to the invoking element when the `<dialog>` is closed via native backdrop click, native cancel events, or item execution from detached elements. Restore focus inside the dialog's native `onClose` callback and verify `triggerRef.current` is connected to the DOM before focusing.
- **Medium** — `src/components/CommandPalette.tsx:313`: The search input has `role="combobox"` but lacks `aria-haspopup="listbox"`, and its `aria-controls` references an ID that is unmounted when no results match. Add `aria-haspopup="listbox"` and preserve the listbox container in the DOM with an empty message instead of conditionally unmounting it.
- **Medium** — `src/components/case-study/Widgets.tsx:142`: Inactive tabs specify `aria-controls={`panel-${widgetId}-${tab.id}`}` pointing to tabpanel IDs that do not exist in the DOM because only the active tabpanel is rendered. Give the tabpanel a constant ID referenced by all tabs or render all tabpanels and toggle visibility with `hidden`.
- **Low** — `src/components/ThemeToggle.tsx:134`: Pairing a dynamic action label (`Switch to light theme`) with `aria-pressed="true"` creates contradictory announcements on screen readers. Remove `aria-pressed` from the action button or switch to a static state label like `aria-label="Dark mode"`.
- **Low** — `src/components/case-study/Toc.tsx:139`: Rendering section index numbers with `text-muted/60` against dark surfaces reduces the contrast ratio below the 4.5:1 WCAG AA threshold required by SPEC hard rules. Remove the opacity modifier and use solid `text-muted`.

## Semantic Regressions

- **Medium** — `src/components/case-study/Metrics.tsx:92`: The stat tile renders `<dd>` before `<dt>` inside a `<dl>`, violating HTML specifications requiring terms to precede descriptions. Place `<dt>` before `<dd>` in the DOM and use flexbox `flex-col-reverse` to position the number above the label visually.
- **Medium** — `src/components/AboutTeaser.tsx:51`: A decorative track `<div>` is placed as a direct child of `<ol>`, violating HTML validation rules and SPEC S list structure requirements. Move the decorative line `<div>` outside the `<ol>` into a wrapping container.
- **Medium** — `src/components/Timeline.tsx:36`: The `<ol>` element contains direct child `<div>` elements for the static track and progress indicator, violating semantic list rules. Move the decorative track elements outside `<ol>` or implement them using CSS pseudo-elements.
- **Low** — `src/components/case-study/Widgets.tsx:103`: Widget titles use `<h4>` directly inside sections whose visible heading is `<h2>`, skipping heading level `<h3>` when no preceding heading block exists in the section. Change widget title headings to `<h3>` to preserve heading hierarchy per SPEC S.
- **Low** — `src/components/Nav.tsx:287`: The mobile sheet navigation omits a link to Home (`/`), preventing mobile users from returning home once the full-height sheet is opened. Add a Home link to the mobile sheet navigation list with `aria-current={isHome ? "page" : undefined}`.

## Performance Issues

- **High** — `src/components/CommandPalette.tsx:6`: `CommandPalette` is a client component mounted on every page that imports `getAllStudies()` from `src/lib/content.ts`, bundling all 9 full case-study JSON files into the global client bundle. Replace `getAllStudies()` with a lightweight static index containing only titles, slugs, domains, and section labels.
- **High** — `src/components/case-study/SectionBlock.tsx:1`: `SectionBlock.tsx` is marked `"use client"` solely to support `IframeWithSkeleton`, forcing all case-study text, lists, and images to be client-rendered across all project pages. Remove `"use client"` from `SectionBlock.tsx` and extract `IframeWithSkeleton` into its own isolated client component.
- **High** — `src/components/IntentPicker.tsx:6`: `IntentPicker` is a client component on the home page that imports `getStudy` from `src/lib/content.ts` to get titles for 2–3 links, bundling all 9 case studies into the home page client payload. Pass pre-resolved title strings or use a lightweight slug-to-title map that does not import the full case-study JSON files.
- **High** — `src/components/WorkCard.tsx:1`: `WorkCard` is marked `"use client"` and imports `src/lib/content.ts` for a pointermove spotlight effect, bundling all case studies into client JS on both the home page and `/work/`. Make `WorkCard` a Server Component and isolate the mouse spotlight tracking into a lightweight client wrapper.
